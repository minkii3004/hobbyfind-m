# HobbyFind Use Case Document

> 서비스명: **HobbyFind**\
> 서비스 타입: **웹서비스**\
> 이용 조건: **비로그인 사용자도 모든 주요 기능 이용 가능**\
> 문서 목적: HobbyFind의 사용자 행동, 시스템 반응, 예외 및 제약사항을
> 정의하여 기획·디자인·개발 시 공통 기준으로 활용한다.

------------------------------------------------------------------------

## 1. 유스케이스 범위

HobbyFind는 사용자가 별도의 로그인 없이 전체 취미를 탐색하거나,
운동형·지능형·예술형 카테고리를 선택하여 해당 카테고리에 포함된 취미를
탐색할 수 있도록 한다.

본 문서에서 다루는 핵심 사용자 행동은 다음과 같다.

1.  루트 페이지 진입 및 전체 취미 탐색
2.  카테고리 선택 및 전용 페이지 이동
3.  카테고리별 취미 탐색
4.  다른 카테고리로 전환
5.  로고를 통한 루트 페이지 복귀
6.  카테고리 URL 직접 접근

본 요구사항에 정의되지 않은 로그인, 검색, 추천, 저장, 좋아요, 상세
페이지 등의 기능은 유스케이스에 포함하지 않는다.

### 2.1 비로그인 사용자

사용자는 계정 생성이나 인증 과정 없이 다음 기능을 이용할 수 있다.

-   루트 페이지 접근
-   전체 취미 18개 탐색
-   운동형 카테고리 선택
-   지능형 카테고리 선택
-   예술형 카테고리 선택
-   각 카테고리 페이지 접근
-   카테고리 간 이동
-   로고를 통한 루트 페이지 이동

### 2.2 시스템

시스템은 다음 역할을 수행한다.

-   요청된 URL에 해당하는 페이지 렌더링
-   고정된 취미 데이터 로드
-   전체 또는 카테고리별 취미 데이터 구분
-   취미 카드 그리드 렌더링
-   카테고리 선택에 따른 페이지 이동
-   현재 카테고리 상태 표시

# 4. 상세 Use Case 시나리오 (Detailed Use Case Scenarios)

## UC-01. 루트 페이지 탐색

### 기본 정보

  항목            내용
  --------------- ----------------------------------------------
  Use Case ID     UC-01
  Use Case Name   루트 페이지 탐색
  Primary Actor   비로그인 사용자
  Trigger         사용자가 HobbyFind 루트 URL `/`에 접근
  목적            서비스 목적을 확인하고 전체 취미 목록을 탐색
  우선순위        필수

### 사전조건 (Preconditions)

-   사용자가 웹 브라우저를 통해 HobbyFind에 접근할 수 있어야 한다.
-   시스템에 고정된 18개의 취미 데이터가 정의되어 있어야 한다.
-   별도의 로그인 상태는 요구하지 않는다.

### 주요 단계 및 이벤트 흐름 (Main Flow)

  -----------------------------------------------------------------------
  Step                    Actor                   행동 / 시스템 반응
  ----------------------- ----------------------- -----------------------
  1                       사용자                  HobbyFind 루트 URL
                                                  `/`에 접근한다.

  2                       시스템                  루트 페이지를
                                                  렌더링한다.

  3                       시스템                  Top Bar에 로고와
                                                  운동형·지능형·예술형
                                                  카테고리를 표시한다.

  4                       시스템                  Hero 영역에 사이트 소개
                                                  문구를 표시한다.

  5                       시스템                  전체 18개 취미 데이터를
                                                  로드한다.

  6                       시스템                  전체 취미를 카드 그리드
                                                  형태로 표시한다.

  7                       사용자                  표시된 취미 카드를
                                                  탐색한다.
  -----------------------------------------------------------------------

### 사후조건 (Postconditions)

-   사용자는 전체 18개의 취미를 확인할 수 있다.
-   사용자는 Top Bar를 통해 원하는 카테고리 페이지로 이동할 수 있는
    상태가 된다.
-   인증 또는 사용자 데이터는 생성되지 않는다.

### 대체 흐름

**AF-01 --- 모바일 또는 작은 화면에서 접근**

1.  사용자가 작은 화면 크기의 기기로 `/`에 접근한다.
2.  시스템은 화면 너비에 맞게 Hobby Grid의 열 수를 조정한다.
3.  동일한 18개 취미를 표시한다.

### 엣지 케이스

**EC-01 --- 고정 데이터 일부 누락**

-   시스템이 18개 미만의 데이터를 로드한 경우 요구 데이터와 실제 렌더링
    결과가 불일치한 상태다.
-   임의의 대체 취미를 생성하거나 추가하지 않는다.
-   데이터 정의를 확인해야 하는 개발 오류로 처리한다.

## UC-02. 카테고리 선택

### 기본 정보

  항목            내용
  --------------- -----------------------------------------
  Use Case ID     UC-02
  Use Case Name   카테고리 선택
  Primary Actor   비로그인 사용자
  Trigger         사용자가 Top Bar의 카테고리 항목을 클릭
  목적            선택한 카테고리의 전용 페이지로 이동
  우선순위        필수

### 사전조건

-   사용자가 루트 또는 카테고리 페이지에 접근한 상태다.
-   Top Bar가 정상적으로 렌더링되어 있다.

### 주요 흐름

  Step   Actor    행동 / 시스템 반응
  ------ -------- ---------------------------------------------------
  1      사용자   Top Bar에서 원하는 카테고리를 선택한다.
  2      시스템   선택된 카테고리에 대응하는 URL을 확인한다.
  3      시스템   해당 카테고리 URL로 이동한다.
  4      시스템   선택된 카테고리 페이지를 렌더링한다.
  5      시스템   Top Bar에서 현재 카테고리를 선택 상태로 표시한다.
  6      시스템   페이지 상단에 카테고리명과 소개 문구를 표시한다.
  7      시스템   해당 카테고리의 취미 6개만 그리드로 표시한다.

### 카테고리-URL 매핑

  사용자 선택   URL               결과
  ------------- ----------------- ----------------------
  운동형        `/exercise`       운동형 취미 6개 표시
  지능형        `/intelligence`   지능형 취미 6개 표시
  예술형        `/art`            예술형 취미 6개 표시

### 사후조건

-   브라우저 URL이 선택한 카테고리 URL로 변경된다.
-   선택한 카테고리에 해당하는 6개의 취미만 표시된다.
-   Top Bar에서 현재 카테고리가 시각적으로 구분된다.

### 대체 흐름

**AF-02 --- 다른 카테고리 페이지에서 카테고리 선택**

-   사용자가 이미 카테고리 페이지에 있더라도 동일한 Top Bar를 통해 다른
    카테고리로 이동할 수 있다.
-   이동 후 URL과 표시 데이터는 새로 선택한 카테고리를 기준으로
    갱신한다.

### 엣지 케이스

**EC-02 --- 현재 페이지와 동일한 카테고리 선택**

-   현재 보고 있는 카테고리와 동일한 카테고리를 다시 선택하더라도 콘텐츠
    범위는 변경되지 않는다.
-   동일 카테고리의 6개 취미를 유지한다.

## UC-03. 카테고리별 취미 탐색

### 기본 정보

  항목            내용
  --------------- --------------------------------------
  Use Case ID     UC-03
  Use Case Name   카테고리별 취미 탐색
  Primary Actor   비로그인 사용자
  Trigger         카테고리 페이지 진입
  목적            선택한 카테고리에 포함된 취미만 확인
  우선순위        필수

### 사전조건

-   사용자가 `/exercise`, `/intelligence`, `/art` 중 하나의 유효한
    카테고리 URL에 접근한 상태다.
-   고정 취미 데이터가 정상적으로 정의되어 있다.

### 주요 흐름

  -----------------------------------------------------------------------
  Step                    Actor                   행동 / 시스템 반응
  ----------------------- ----------------------- -----------------------
  1                       시스템                  현재 URL에 대응하는
                                                  카테고리를 식별한다.

  2                       시스템                  해당 카테고리명과 소개
                                                  문구를 표시한다.

  3                       시스템                  전체 취미 데이터 중
                                                  현재 카테고리에
                                                  해당하는 데이터를
                                                  구분한다.

  4                       시스템                  해당 카테고리의 취미
                                                  6개를 Hobby Grid에
                                                  전달한다.

  5                       시스템                  6개의 취미 카드를
                                                  그리드로 렌더링한다.

  6                       사용자                  표시된 취미 목록을
                                                  탐색한다.
  -----------------------------------------------------------------------

### 카테고리별 표시 데이터

  -----------------------------------------------------------------------
  카테고리                            표시 취미
  ----------------------------------- -----------------------------------
  운동형                              조깅/러닝, 요가, 수영, 자전거,
                                      클라이밍, 댄스

  지능형                              독서, 퍼즐, 체스, 프로그래밍,
                                      외국어 학습, 사진 촬영

  예술형                              그림 그리기, 악기 연주, 요리, 서예,
                                      도자기 만들기, 정원 가꾸기
  -----------------------------------------------------------------------

### 사후조건

-   현재 카테고리에 해당하는 정확히 6개의 취미가 표시된다.
-   다른 카테고리의 취미는 해당 목록에 표시되지 않는다.

### 엣지 케이스

**EC-03 --- 잘못된 category 값의 데이터 존재**

-   정의된 카테고리는 `exercise`, `intelligence`, `art`만 허용한다.
-   정의되지 않은 category 값을 가진 데이터는 정상 데이터로 간주하지
    않는다.
-   임의로 기존 카테고리에 배정하지 않는다.

# 7. 비즈니스 규칙 및 제약사항 (Business Rules and Constraints)

## 7.1 카테고리 규칙

카테고리는 아래 3개로 고정한다.

``` text
운동형
지능형
예술형
```

새로운 카테고리를 추가하지 않는다.

## 7.2 취미 데이터 규칙

-   전체 취미는 18개로 고정한다.
-   각 카테고리는 6개의 취미를 가진다.
-   취미 목록을 변경하거나 확장하지 않는다.
-   하나의 취미는 정의된 하나의 카테고리에 속한다.

## 7.3 이용 규칙

-   로그인 없이 모든 주요 페이지에 접근할 수 있다.
-   회원 인증을 요구하지 않는다.
-   카테고리 URL 직접 접근을 허용한다.

## 7.4 기능 범위 제약

다음 기능은 포함하지 않는다.

-   로그인 / 회원가입
-   검색
-   추천
-   개인화
-   좋아요 / 즐겨찾기
-   저장
-   리뷰 / 댓글
-   취미 상세 페이지
-   취미 등록 / 수정 / 삭제
-   사용자 프로필
-   관리자 기능
-   요구사항에 정의되지 않은 추가 기능

# 8. 예외 처리 절차 (Exception Handling Procedures)

## 8.1 데이터 불일치

### 조건

-   전체 취미 수가 18개가 아님
-   특정 카테고리의 취미 수가 6개가 아님
-   정의되지 않은 카테고리 값이 존재함

### 처리

``` text
데이터 로드
   │
   ▼
정의된 데이터 규칙과 불일치
   │
   ▼
임의 데이터 생성 금지
   │
   ▼
개발 단계에서 데이터 정의 확인 및 수정
```

고정 데이터 기반 서비스이므로 누락된 취미를 시스템이 임의로 생성해서는
안 된다.

## 8.2 잘못된 URL

정의된 페이지는 다음 네 경로다.

``` text
/
/exercise
/intelligence
/art
```

그 외 정의되지 않은 경로는 Next.js의 기본 Not Found 처리 기준을 따른다.

## 8.3 페이지 렌더링 오류

페이지 또는 컴포넌트 렌더링 오류가 발생하더라도 요구사항에 없는 대체
콘텐츠나 기능을 자동 생성하지 않는다.

# 11. 보안 및 개인정보 고려사항 (Security and Privacy Considerations)

## 11.1 인증

HobbyFind의 주요 기능은 비로그인 상태에서 제공되므로 사용자 인증 정보를
요구하지 않는다.

## 11.2 개인정보

현재 정의된 기능 범위에서는 다음 개인정보를 수집하거나 저장할 필요가
없다.

-   이름
-   이메일
-   전화번호
-   계정 정보
-   프로필 정보
-   사용자가 선택한 취미에 대한 개인별 저장 정보

## 11.3 데이터 저장

-   취미 정보는 서비스에서 제공하는 고정 콘텐츠 데이터다.
-   사용자별 취미 선택 내역을 저장하지 않는다.
-   사용자 프로필 또는 개인화 데이터를 생성하지 않는다.

## 11.4 보안 범위

사용자 입력을 받아 서버에 저장하거나 인증 정보를 처리하는 기능이
없으므로 본 범위에서는 계정·인증 기반 보안 절차가 필요하지 않다.

웹서비스 구현 시 기본적인 안전한 프레임워크 구성 및 배포 환경의 보안
기준을 따른다.

# 13. 유스케이스 완료 기준

다음 조건을 충족하면 본 문서에서 정의한 핵심 유스케이스가 정상 구현된
것으로 판단한다.

-   비로그인 사용자가 `/`에 접근할 수 있다.
-   `/`에서 정확히 18개의 고정 취미를 탐색할 수 있다.
-   운동형 선택 시 `/exercise`로 이동한다.
-   지능형 선택 시 `/intelligence`로 이동한다.
-   예술형 선택 시 `/art`로 이동한다.
-   각 카테고리 페이지에서 정확히 해당 카테고리의 6개 취미만 표시된다.
-   카테고리 페이지에서 현재 카테고리가 선택 상태로 표시된다.
-   다른 카테고리로 정상 전환할 수 있다.
-   로고를 선택하면 `/`로 이동한다.
-   카테고리 URL에 직접 접근해도 정상 렌더링된다.
-   고정된 18개 이외의 취미가 임의로 추가되지 않는다.
-   요구사항에 정의되지 않은 추가 기능이 구현되지 않는다.
