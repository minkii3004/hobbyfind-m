# HobbyFind PRD

> Product Requirements Document\
> 서비스명: **HobbyFind**\
> 서비스 타입: **웹서비스**\
> 이용 조건: **비로그인 사용자 이용 가능**

## 1. 제품 상세 설명 (Detailed Product Description)

### 1.1 서비스 설명

HobbyFind는 사용자가 다양한 취미를 **운동형, 지능형, 예술형**의 3개
카테고리를 기준으로 탐색하고 선택할 수 있도록 돕는 웹서비스다.

사용자는 별도의 로그인이나 회원가입 없이 루트 페이지에서 전체 취미
목록을 확인할 수 있다. 상단 카테고리 필터를 선택하면 해당 카테고리에
속하는 취미만 모아 제공하는 전용 페이지로 이동한다.

본 서비스에서 제공하는 취미는 아래 18개로 고정하며 변경하거나 확장하지
않는다.

  -----------------------------------------------------------------------
  카테고리                            취미
  ----------------------------------- -----------------------------------
  운동형                              조깅/러닝, 요가, 수영, 자전거,
                                      클라이밍, 댄스

  지능형                              독서, 퍼즐, 체스, 프로그래밍,
                                      외국어 학습, 사진 촬영

  예술형                              그림 그리기, 악기 연주, 요리, 서예,
                                      도자기 만들기, 정원 가꾸기
  -----------------------------------------------------------------------

### 1.2 핵심 목표

1.  전체 취미 목록을 한 화면에서 쉽게 탐색할 수 있도록 한다.
2.  운동형·지능형·예술형의 명확한 분류를 통해 관심 있는 취미 유형을
    빠르게 탐색할 수 있도록 한다.
3.  로그인 없이 즉시 취미 탐색이 가능하도록 한다.
4.  루트 페이지와 카테고리별 페이지를 일관된 카드 기반 UI로 제공한다.

### 1.3 서비스 범위

서비스는 아래 페이지로 구성한다.

> **구현 현황 메모 (2026-09-29 기준)**\
> 카테고리 전용 페이지(`/exercise`, `/intelligence`, `/art`)는 아직 구현되지
> 않았으며, 현재는 루트 페이지의 카테고리 탭 필터가 그 역할을 대신한다.
> 추가로 구현된 기능은 [3.8 추가 구현 사항](#38-추가-구현-사항)에 정리한다.

-   루트 페이지
-   운동형 카테고리 페이지
-   지능형 카테고리 페이지
-   예술형 카테고리 페이지
-   취미 상세 페이지 (`/hobbies/[id]`)

## 2. 참고 서비스 및 근거 (Reference Services with Detailed Rationale)

참고 서비스는 **정보 구조와 탐색 UI 패턴의 참고 기준**으로만 사용한다.
해당 서비스가 제공하는 별도 기능을 HobbyFind에 추가하지 않는다.

  -----------------------------------------------------------------------
  참고 서비스             참고 요소               참고 근거
  ----------------------- ----------------------- -----------------------
  Pinterest               카드 중심 콘텐츠 탐색   여러 관심 항목을 카드
                                                  단위로 빠르게 훑어볼 수
                                                  있는 콘텐츠 배열 방식
                                                  참고

  Airbnb                  상단 카테고리 탐색      사용자가 관심
                                                  카테고리를 선택하고
                                                  해당 범위의 콘텐츠를
                                                  탐색하는 정보 구조 참고

  Netflix                 반복적인 콘텐츠 카드    동일한 구조의 콘텐츠를
                          배열                    반복 배치해 목록을
                                                  빠르게 스캔할 수 있는
                                                  패턴 참고
  -----------------------------------------------------------------------

### 적용 원칙

-   참고 서비스의 기능을 그대로 구현하지 않는다.
-   카테고리 탐색과 카드 그리드 구조만 참고한다.
-   본 PRD에 정의되지 않은 검색, 추천, 개인화, 서버 저장, 회원 기능 등은
    추가하지 않는다. (브라우저 로컬 저장 기반의 선호 취미 하트는 3.8에서
    별도로 정의한다.)

## 3. 핵심 기능 및 사양 (Core Features and Specifications)

### 3.1 정보 구조

``` text
/
├── /exercise
├── /intelligence
├── /art
└── /hobbies/[id]
```

  경로              페이지          노출 콘텐츠
  ----------------- --------------- -----------------
  `/`               루트 페이지     전체 18개 취미
  `/exercise`       운동형 페이지   운동형 6개 취미
  `/intelligence`   지능형 페이지   지능형 6개 취미
  `/art`            예술형 페이지   예술형 6개 취미
  `/hobbies/[id]`   취미 상세 페이지 선택한 취미 1개 상세 정보

### 3.2 루트 페이지

#### 목적

서비스의 목적을 소개하고 전체 취미를 탐색할 수 있도록 하며, 사용자가
관심 카테고리의 전용 페이지로 이동할 수 있도록 한다.

#### 화면 구성

  -----------------------------------------------------------------------
  영역                    구성 요소               요구사항
  ----------------------- ----------------------- -----------------------
  Top Bar                 로고                    HobbyFind 로고를
                                                  표시한다.

  Top Bar                 카테고리 필터           운동형, 지능형, 예술형
                                                  3개 항목을 제공한다.

  Hero                    사이트 소개 문구        HobbyFind의 목적을 짧게
                                                  설명한다.

  Main Content            취미 카드 그리드        전체 18개 취미 카드를
                                                  표시한다.
  -----------------------------------------------------------------------

#### 동작 규칙

-   최초 진입 시 전체 18개 취미를 표시한다.
-   로그인 여부와 관계없이 모든 콘텐츠를 확인할 수 있다.
-   `운동형` 선택 시 운동형 전용 페이지로 이동한다.
-   `지능형` 선택 시 지능형 전용 페이지로 이동한다.
-   `예술형` 선택 시 예술형 전용 페이지로 이동한다.
-   취미 카드는 그리드 형태로 배치한다.

### 3.3 카테고리별 페이지

#### 공통 구성

  -----------------------------------------------------------------------
  영역                    구성 요소               요구사항
  ----------------------- ----------------------- -----------------------

#### 운동형 페이지

노출 취미: - 조깅/러닝 - 요가 - 수영 - 자전거 - 클라이밍 - 댄스

#### 지능형 페이지

노출 취미: - 독서 - 퍼즐 - 체스 - 프로그래밍 - 외국어 학습 - 사진 촬영

#### 예술형 페이지

노출 취미: - 그림 그리기 - 악기 연주 - 요리 - 서예 - 도자기 만들기 -
정원 가꾸기

### 3.4 카테고리 필터

카테고리 필터는 각 카테고리 전용 페이지로 이동하는 내비게이션 역할을
한다.

  선택 항목   이동 경로
  ----------- -----------------
  운동형      `/exercise`
  지능형      `/intelligence`
  예술형      `/art`

카테고리 페이지에서는 현재 선택된 카테고리가 무엇인지 시각적으로
구분한다.

각 카테고리 URL로 직접 접근하는 경우에도 해당 페이지가 정상적으로
렌더링되어야 한다.

### 3.5 취미 카드

모든 취미는 동일한 카드 컴포넌트를 사용한다.

#### 필수 표시 정보

-   취미명
-   해당 취미를 식별할 수 있는 시각 요소

#### 표시 규칙

-   루트 페이지: 전체 18개 카드
-   카테고리 페이지: 해당 카테고리 6개 카드
-   동일한 카드 구조와 기본 레이아웃 규칙을 사용한다.
-   화면 너비에 따라 카드 그리드의 열 수가 조정되는 반응형 구조로
    구현한다.
-   카드 선택 시 해당 취미의 상세 페이지로 이동한다. (3.8 참조)

### 3.6 Hero 섹션

Hero는 루트 페이지에만 표시한다.

필수 요소: - 서비스 식별 문구 - HobbyFind의 목적을 설명하는 짧은 소개
문구

검색창, 로그인 유도, 추천 기능 등 요구사항에 없는 요소는 추가하지
않는다.

### 3.8 추가 구현 사항

초기 요구사항 이후 추가로 구현된 페이지와 기능을 정의한다. 본 절의 내용이
앞선 절과 충돌하는 경우 본 절을 우선한다.

#### 3.8.1 루트 페이지 카테고리 탭

  항목        내용
  ----------- --------------------------------------------------------
  위치        Hero 아래 Main Content 상단 (스크롤 시 Top Bar 아래 고정)
  탭 구성     전체, 운동형, 지능형, 예술형
  기본 선택   전체
  동작        페이지 이동 없이 같은 화면에서 취미 목록을 필터링한다.
  전체 탭     카테고리가 연달아 나열되지 않도록 카테고리를 번갈아
              배치해 18개를 모두 노출한다.
  선택 상태   primary 컬러 배경 + 흰색 텍스트
  Top Bar     로고만 배치한다. (카테고리 필터는 본문 탭으로 이동)

#### 3.8.2 취미 카드 확장

-   썸네일 좌측 상단에 카테고리 뱃지(primary 배경, 흰색 텍스트)를
    표시한다.
-   썸네일 우측 상단에 선호 취미 하트 버튼을 제공한다.
-   카드를 클릭하면 취미 상세 페이지(`/hobbies/[id]`)로 이동한다.
-   썸네일은 `public/thumbnails/{id}.svg`의 고정 이미지를 사용한다.
-   Hover 시 썸네일이 확대(scale 1.10)된다.

**하트(선호 취미) 규칙**

  상태                 표시
  -------------------- ------------------------------------------------
  기본 (미선택)        primary 컬러 윤곽선 하트
  Hover (미선택)       하트 내부가 연한 primary 컬러로 채워짐
  클릭 (선택)          primary 컬러로 채워진 하트
  선택된 상태          Hover 효과 없음
  선택 해제 직후       Hover 중이어도 윤곽선 하트로 표시

-   선택 상태는 브라우저 localStorage에 저장되어 새로고침 후에도 유지된다.
-   계정, 서버 저장, 별도의 즐겨찾기 목록 페이지는 제공하지 않는다.

#### 3.8.3 취미 상세 페이지 `/hobbies/[id]`

취미 카드를 선택했을 때 이동하는 페이지다. `[id]`는 18개 고정 취미의 id
값(예: `running`, `chess`, `language-learning`)이다.

**화면 구성**

  영역             구성 요소
  ---------------- -----------------------------------------------------
  Top Bar          로고 (공통)
  Back Link        "전체 취미" (`/`로 이동)
  Overview         썸네일, 취미명, 하트 버튼, 소개 문구
  취미 정보        카테고리, 난이도, 예상 비용, 추천 시간, 주요 장소
  Detail Section   이런 효과가 있어요 / 이런 분께 추천해요 / 준비물 /
                   이렇게 시작해 보세요
  Related Hobbies  같은 카테고리의 다른 취미 5개 (HobbyGrid 재사용)

-   상세 페이지의 썸네일에는 카테고리 뱃지를 표시하지 않고, 카테고리는
    취미 정보 영역에 정보 형태로 표시한다.
-   존재하지 않는 id로 접근하면 Next.js 기본 Not Found(404)를 표시한다.
-   로그인 없이 직접 URL 접근이 가능하다.
-   빌드 시 18개 경로가 정적으로 생성된다. (`generateStaticParams`)

**취미 데이터 필드**

  필드             타입        설명
  ---------------- ----------- ---------------------------------------
  `description`    string      취미 소개 문구
  `info`           object      난이도 / 예상 비용 / 추천 시간 / 주요 장소
  `benefits`       string[]    취미가 주는 효과 (3개)
  `recommendedFor` string[]    추천 대상 (3개)
  `supplies`       string[]    준비물 (3개)
  `tips`           string[]    시작 팁 (3개)

  페이지          title                          description / keywords
  --------------- ------------------------------ ------------------------------
  루트 `/`        HobbyFind \| 나에게 맞는       서비스 소개 문구 / 취미, 취미
                  취미를 발견하세요               추천, 취미 찾기, 카테고리별

  `/hobbies/[id]` HobbyFind`                     추천 시간, 카테고리 /

                                                 취미`, 취미 추천, 취미 찾기

-   Open Graph(title, description, locale)를 함께 설정한다.

## 4. 사용자 페르소나 및 시나리오 (User Persona and Scenarios)

### 4.1 사용자 페르소나

  -----------------------------------------------------------------------

### 4.2 시나리오 A --- 전체 취미 탐색

1.  사용자가 HobbyFind 루트 페이지에 접속한다.
2.  Hero 영역에서 사이트의 목적을 확인한다.
3.  메인 콘텐츠에서 전체 18개 취미를 탐색한다.

**완료 조건:** 별도 로그인 없이 전체 취미 목록을 확인할 수 있다.

### 4.3 시나리오 B --- 운동형 취미 탐색

1.  사용자가 루트 페이지에 접속한다.
2.  Top Bar에서 `운동형`을 선택한다.
3.  `/exercise`로 이동한다.
4.  페이지 상단에서 운동형 카테고리명과 소개 문구를 확인한다.
5.  운동형에 속한 6개의 취미를 확인한다.

**완료 조건:** 운동형 이외의 취미가 목록에 표시되지 않는다.

### 4.4 시나리오 C --- 카테고리 페이지 직접 접근

1.  사용자가 `/intelligence` URL에 직접 접근한다.
2.  로그인 과정 없이 페이지가 열린다.
3.  지능형 카테고리명과 소개 문구를 확인한다.
4.  지능형에 속한 6개의 취미를 확인한다.

**완료 조건:** 루트 페이지를 거치지 않아도 카테고리 페이지가 정상적으로
표시된다.

### 4.5 시나리오 D --- 카테고리 전환

1.  사용자가 예술형 페이지를 보고 있다.
2.  Top Bar에서 `운동형`을 선택한다.
3.  `/exercise`로 이동한다.
4.  운동형 6개 취미가 표시된다.

**완료 조건:** URL과 표시 콘텐츠가 선택한 카테고리에 맞게 변경된다.

### 5.4 취미 데이터 구조

취미 데이터는 하나의 정적 데이터 소스에서 관리한다.

``` ts
type HobbyCategory = 'exercise' | 'intelligence' | 'art';

interface HobbyInfo {
  difficulty: string;
  cost: string;
  duration: string;
  place: string;
}

interface Hobby {
  id: string;
  name: string;
  category: HobbyCategory;
  description: string;
  info: HobbyInfo;
  benefits: string[];
  recommendedFor: string[];
  supplies: string[];
  tips: string[];
}
```

### 5.5 데이터 처리

별도의 백엔드나 데이터베이스를 요구하지 않는다.

카테고리별 페이지는 공통 취미 데이터에서 `category` 값을 기준으로 필요한
항목만 필터링한다.

``` ts
const exerciseHobbies = hobbies.filter(
  (hobby) => hobby.category === 'exercise'
);
```

동일한 취미 데이터를 각 페이지에 중복 선언하지 않는다.

### 5.6 반응형 웹 요구사항

-   PC와 모바일 화면에서 모두 이용 가능해야 한다.
-   카드가 화면 영역 밖으로 잘리지 않아야 한다.
-   화면 너비에 따라 그리드 열 수를 조정한다.
-   카드 간 간격을 일관되게 유지한다.
-   모바일에서도 취미명이 정상적으로 읽혀야 한다.
-   모든 화면 크기에서 Top Bar의 카테고리 이동 기능을 사용할 수 있어야
    한다.

## 6. 제한사항 (Limitations)

본 PRD의 구현 범위는 사용자가 명시한 페이지 및 기능으로 제한한다.

### 6.1 고정 데이터

-   취미는 총 18개로 고정한다.
-   카테고리는 운동형, 지능형, 예술형 3개로 고정한다.
-   취미 및 카테고리를 추가하거나 확장하지 않는다.

### 6.2 페이지 범위

다음 페이지만 구현 범위에 포함한다.

1.  루트 페이지
2.  운동형 페이지
3.  지능형 페이지
4.  예술형 페이지
5.  취미 상세 페이지 (`/hobbies/[id]`)

### 6.3 제외 기능

다음 기능은 본 PRD의 범위에 포함하지 않는다.

-   로그인 및 회원가입
-   사용자 계정 및 프로필
-   취미 검색
-   취미 추천
-   개인화
-   서버 저장 기반 좋아요 / 즐겨찾기 (브라우저 로컬 저장 하트는 3.8에서
    허용)
-   저장 기능
-   리뷰 또는 댓글
-   취미 등록·수정·삭제
-   관리자 페이지
-   사용자별 활동 기록
-   알림 기능
-   결제 기능
-   요구사항에 정의되지 않은 추가 페이지

### 6.4 개발 원칙

-   요구사항에 명시되지 않은 기능을 임의로 추가하지 않는다.
-   UI 구현 과정에서 새로운 사용자 기능을 추가하지 않는다.
-   디자인상의 표현 방식은 조정할 수 있으나 정보 구조와 기능 범위는 본
    PRD를 따른다.

## 7. 개발 완료 기준

아래 조건을 모두 충족하면 본 PRD 기준의 핵심 구현이 완료된 것으로 본다.

-   `/`에서 전체 18개 취미가 표시된다.
-   운동형·지능형·예술형 카테고리 이동이 정상 동작한다.
-   각 카테고리 페이지에는 정확히 해당 카테고리의 6개 취미만 표시된다.
-   카테고리 페이지에 카테고리명과 소개 문구가 표시된다.
-   모든 페이지를 로그인 없이 이용할 수 있다.
-   PC와 모바일 웹에서 콘텐츠를 탐색할 수 있다.
-   고정된 18개 외의 취미가 노출되지 않는다.
-   `/hobbies/[id]`에서 18개 취미 각각의 상세 정보가 표시된다.
-   루트 및 상세 페이지에 title, description, keywords가 설정된다.
-   본 PRD에서 제외한 추가 기능이 구현되지 않는다.
